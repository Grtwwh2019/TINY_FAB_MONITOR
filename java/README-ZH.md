# TINY FAB MONITOR Java 8 版

这是不启动网页服务的 Java Swing 桌面版本，适用于 Windows 10/11 x64。最终 Fat JAR 已包含 Oracle JDBC 和 JSON 持久化依赖，运行电脑只需准备 64 位 JRE 8。

## 运行

将构建得到的 `TinyFabMonitor.jar`、复制并改名后的 `config.properties` 放在同一目录。首次运行建议使用命令提示符，以便看到错误：

```bat
"C:\你的JRE目录\bin\java.exe" -jar TinyFabMonitor.jar
```

确认正常后可使用无命令窗口的方式：

```bat
"C:\你的JRE目录\bin\javaw.exe" -jar TinyFabMonitor.jar
```

## 配置

复制 `config.example.properties` 为 `config.properties`，填写 Oracle 地址、端口、服务名、账号、密码、业务日期和四个业务表名。示例中的表名均为公开占位名，四项表名必须替换为实际值；支持 `TABLE` 或 `SCHEMA.TABLE` 格式。

如不希望把密码写入配置文件，可在 `oracle.password_env` 中填写 Windows 环境变量名。

## 数据和安全行为

- 启动后立即查询一次；此后每次查询结束，默认在 4–6 分钟之间重新随机安排下一次查询。界面显示实际的下次刷新时间。
- 仅程序窗口保持打开时定时运行。
- 数据保存在 `data/state.json`，日志保存在 `data/oracle-fab-monitor-java.log`。
- 数据始终使用普通 JSON，不在启动或关闭时压缩。
- 兼容原 Go/EXE 版的 `state.json`。
- 不创建或修改 Windows 服务、注册表、计划任务、防火墙规则或开机启动项。
- 不调用 PowerShell、`rundll32`、浏览器或其他外部程序。
- 不启动本地网页服务器，不监听端口。

## 当前任务与 DAG

- “任务状态”显示当前业务日期查询到的全部状态，不仅限于 `R`。
- Oracle 查询只按业务日期过滤，不在 SQL 中限制 Level No。
- 任务表可以输入 Level No 起止区间；只填一端表示单边范围，起止值均包含在结果中。
- FAB ID 和 FAB 描述使用独立列；Thread ID 输入框使用忽略大小写的包含匹配。
- Thread、Level、状态和关键字筛选只影响任务表。
- DAG 默认不查询、不显示节点。DAG 页面提供 Thread ID、Level No、FAB ID 三个输入框，点击“搜索定位”后才按需加载目标 FAB 的依赖图。
- 如果搜索条件匹配多个任务，程序会先显示候选列表供选择。
- 配置项 `monitor.dag_upstream_levels` 和 `monitor.dag_downstream_levels` 决定 DAG 页面初始层数，默认均为 5。界面可分别输入 `0–15`，修改在下一次搜索或右键查询时生效，`0` 表示不查询该方向。
- 依赖图向上递归查询所有前置依赖，向下递归查询所有后续 FAB；非当前业务日期的任务不会显示，也不会继续穿过它递归。
- “隐藏状态 R”可即时隐藏已完成节点及其连线，不重新查询数据库；中心 FAB 始终保留。
- 状态不是 `R` 的节点高亮，`E` 使用异常色。节点悬浮提示显示 FAB 描述、Thread、Level、状态时间、I 开始时间、本次/当前时长和历史平均。
- 搜索中心 FAB 后，DAG 顶部和中心节点悬浮会显示预计完成时间。ETA 的上游计算不受画面 `0–15` 层限制：W 节点继续向上，遇到有效 R 或 I 时间停止；E/B 会标记阻塞。
- 有效 R 的 `act_tm` 作为路径时间起点。R 时间为数据库占位值时继续向上寻找有效起点，并把该 R 自身的历史平均时长加入路径；多条依赖选择预计完成最晚的一条关键路径。
- 依赖表在首次使用 DAG 或耗时分析时整表只读一次并在内存建立双向索引；后续 DAG 搜索和 ETA 都使用本地缓存。有效 R、I、E、B 不再继续展开，循环依赖会明确提示而不会无限计算。
- 右键任意已显示节点可选择“展示此 FAB 的依赖 DAG”，将它作为新的中心重新查询。
- 任务页显示全部唯一任务，可按 `W/I/E/B/R` 状态和关键字组合筛选。
- DAG 支持输入 FAB ID 搜索，自动将对应节点移动到画布中心并高亮。

## 运行历史与手动清理

- 运行历史显示并持久化 FAB 描述；旧数据能从当前任务匹配时显示描述，否则显示 `--`。
- 运行历史页可输入 `14–3650` 天并点击“清理数据”。程序以数据中最新 `prcss_dt` 为基准，只在确认后删除窗口之前的 `tracked` 和 `runs` 详细记录。
- 清理前会保存带时间戳的完整 `state.json.before-cleanup-*.bak`，每次备份独立保存；超过24小时的清理备份会在启动或下次清理时删除。
- 清理后，历史平均运行时长根据剩余的运行记录自动重新计算。
- 只要有1次完整 I→R 记录即可显示并用于历史平均；多次记录使用算术平均。没有完整记录的节点不能参与 ETA 补算。

## 耗时分析

- “耗时分析”页面只在点击“开始分析”时访问数据库，不加入自动刷新，也不允许多个分析并发执行。
- 必须指定开始任务和结束任务，均使用 `Thread ID + Level No + FAB ID` 唯一定位。配置文件可提供默认值，页面修改仅对本次运行有效。
- 结束任务进入 `R` 且具有有效 `act_tm`，即认定该业务日期的分析区间已经完成；同一天其他任务不是 R 或缺少时间，不会让整个日期失效。
- 默认向前查找最近一个“结束任务已经 R”的业务日期；也可以指定日期，或选择最近 `2–30` 个结束任务已完成日期平均。
- 可按 Thread ID 包含条件和 Level No 区间缩小分析范围。
- 整体耗时固定为“结束任务 R 时间 − 开始任务开始时间”。开始时间优先使用程序捕获的 I；没有 I 时依次使用“开始任务 R − 更早历史平均时长”和开始任务 R，并明确标记估算精度。
- 当天和基准都有本地 I/R 时，分析执行时长差、前置任务完成后的等待差及异常；只有数据库 R 时，只分析相对完成偏移，不会误判为执行慢或等待慢。
- 某个普通任务缺少有效 R 时，只将该任务标记为“数据不足”，不会阻止其他具有有效 R 的任务参加比较。
- 差异表按延迟贡献排序；差异 DAG 用红/橙/绿区分主要延迟、完成偏移和正常节点，可选择只显示实际关键路径。
- 结束任务尚未完成时，会仅针对结束任务使用完整上游 ETA 预测完成时间；无法预测时只显示当前已运行时间和数据不足原因。
- 数据库性能保护：结束日期候选只用结束任务的唯一键做一次窄查询；每个业务日期的完整任务集最多读取一次，最多缓存最近使用的64个日期，然后在本地筛选和计算。
- Level 描述表和 FAB 描述表在首次任务读取时各整表只读一次并缓存；任务状态 SQL 不再为每一行执行描述相关子查询。依赖表也只在首次 DAG/分析时整表读取一次，后续上下游计算全部在本地完成。
- 缓存只存在于当前程序进程，不写入 `state.json`；重启程序会重新读取基础表，从而取得表结构数据的最新版本。自动刷新、DAG 和耗时分析仍禁止并发访问 Oracle，所有 SQL 均设置超时且不写数据库。

默认边界任务配置（可全部留空，之后在页面填写）：

```properties
monitor.analysis_start_thread_id=
monitor.analysis_start_level_no=
monitor.analysis_start_fab_id=
monitor.analysis_end_thread_id=
monitor.analysis_end_level_no=
monitor.analysis_end_fab_id=
```

## 随机刷新配置

```properties
monitor.poll_interval_min_minutes=4
monitor.poll_interval_max_minutes=6
```

- 单位为分钟，范围两端都可能被选中；合法值为 `1–1440`，最小值不能大于最大值。
- 每次查询成功或失败后重新抽取下一间隔，查询不会重叠。
- 旧配置只有 `monitor.poll_interval_minutes` 时仍按固定间隔运行。

## 构建

开发电脑需要 JDK 8 和 Maven：

```bash
cd java
mvn clean package
```

生成文件为 `java/target/TinyFabMonitor.jar`。Oracle JDBC、Jackson 等运行依赖会由 Maven Shade 合并进该 JAR。

## 准确性

程序以数据库的 `act_tm` 为准。轮询间隔之间快速出现并结束的状态可能无法捕获。捕获 `E → I` 或 `E → B → I` 时，会以新的 `I.act_tm` 刷新运行开始时间。

`act_tm` 同时兼容 Oracle `DATE/TIMESTAMP`，以及形如 `2026-08-01-19.18.09.582000` 的 `CHAR` 字段。CHAR 中超过毫秒的精度会安全截断到毫秒，而界面和持续时长仍按秒展示。

数据库中的 `0001-01-01-00.00.00.000000` 被视为“无有效时间”占位值：任务和状态仍显示，但该值不参与 `I/E/R` 时间记录、持续时长或平均值计算。程序也会自动兼容旧 `state.json` 中由时区换算产生的 `+0000-...`，修复前在数据目录创建 `state.json.before-placeholder-repair.bak`。
